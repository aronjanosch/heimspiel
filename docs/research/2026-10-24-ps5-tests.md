# Manual tests on a homebrew PS5 (2026-10-24)

Checks the open points from [2026-10-24-ps5-feasibility.md](2026-10-24-ps5-feasibility.md) on real
hardware. Console: PS5 (original model), firmware 12.70, Relapse exploit, kstuff-lite 1.11,
ShadowMountPlus 1.7beta7, ftpsrv 0.21.1 (FTP on 2121), elfldr on 9021. Desktop: Arch/Omarchy on the same
LAN. RomM 5.4.1 behind a reverse proxy that redirects HTTP to HTTPS. All transfers were FTP from the
desktop; the prototype scripts lived outside this repository.

## Overview

| # | Test | Result |
|---|---|---|
| 1 | Install an app from the ProsperoStore catalog API over FTP | works; the store adopts the app for updates |
| 2 | Forwarder with `--rom` to PS5SX2 | the launcher starts PS5SX2, but PS5SX2 ignores the arguments |
| 3 | Forwarder with `--rom` + `--core` to PS5 RetroArch | works: the game starts directly |
| 4 | ROM and BIOS from RomM onto the console | works through the API; BIOS placement has pitfalls |
| 5 | RommPS against RomM | works over HTTPS only; places files but writes no playlists |
| 6 | Games in PS5 RetroArch's EmulationStation | come from playlists plus a content scan with a bug |
| 7 | Background services while RetroArch runs | unreachable until RetroArch is closed |

## 1. Install from the catalog API

`GET https://prosperostore.net/api/v1/apps/<TITLE_ID>.json` returns `artifact_url`, `sha256` and `size`.
Download, check the SHA-256, unpack, upload the folder that holds `sce_sys/` to `/data/homebrew/<TITLE_ID>`.
Tested with PS5SX2 (6 files), RommPS (144 files), PS5 RetroArch (19,414 files, 1.5 GB, about 9 minutes
over FTP), Porpoise, PSP5, PSFlyCast and ProsperoEden.

ShadowMountPlus registers the folder on its next scan (`Installing: <name>` … `Installed NEW!` in
`/data/shadowmount/debug.log`). Once, a running instance did not pick up new folders for 40 minutes; a
freshly sent instance found them at once. Trigger a scan through its API (`/api/v1/scan`) and check the
result instead of relying on the interval.

The ProsperoStore listed the FTP-installed apps as installed and offers their updates, so an Output can
install this way without working around the store.

## 2. Forwarder to PS5SX2

Forwarder built per the PS5 Forwarder Format v1 (template `eboot.bin` and `sce_module/libc.prx`, own
`param.json`, `forwarder.json` with `target` `PPSA99203` and `args` `["--rom", "/data/PCSX2/games/<file>.iso"]`),
staged as `.<ID>.tmp` and renamed into `/data/homebrew/`. ShadowMountPlus installed it; the tile started.

The launcher log (`/data/forwarder-manager/launcher.log`) shows both arguments passed and the expected
reply (stage 3, `0x80940010` = queued). PS5SX2 then opens its shelf with the game preselected, but does
not boot it. Its `main()` takes no arguments (`ps5/coreorbis/main-boot.cpp:3299`); the preselection is
`lastgame.txt`. The registry entry "PS5SX2 accepts `--rom`" does not hold for build vk-285-177.
PS5SX2 has its own game tiles instead: a copy of the app with `/app0/game-tile.txt` naming one game
(`main-boot.cpp:3442-3466`). An open issue asks for forwarder support
(github.com/Swordpdf/PS5SX2/issues/61).

## 3. Forwarder to PS5 RetroArch

`target` `PPSA99169`, `args` `["--rom", "/data/roms/snes/<file>.zip", "--core", "snes9x", "--exit-after-game"]`.
The game started directly in Snes9x, without the frontend picker. Matches the README's forwarder section.

## 4. ROMs and BIOS from RomM

- `GET /api/roms?platform_ids=<id>` and `GET /api/roms/<id>/content/<fs_name>` with a client token; a
  3.1 GB ISO downloaded and uploaded unchanged.
- `POST /api/firmware?platform_id=<id>` with multipart `files` uploads BIOS files; RomM stores them under
  `bios/<platform>/` and marks known hashes as verified.
- Placement on the console differs per emulator and is not what a flat copy gives:
  PS5SX2 reads `/data/PCSX2/bios/`; PS5 RetroArch wants the PS2 BIOS in `system/pcsx2/bios/` and Saturn
  in `system/Saturn/` (README "Your files").
- PS5SX2 booted with a Japan v1.00 BIOS (`emulog.txt`: "BIOS Found: Japan v01.00", "isoFile open ok").

## 5. RommPS

- RomM 5.2.0 or newer is required; the console pairing worked with 5.4.1.
- With the server entered as `http://`, every request failed with 401: the proxy's 301 to HTTPS drops the
  `Authorization` header. `https://` works. Always store the RomM URL with `https://`.
- RommPS places ROMs per emulator profile and can feed several emulators per platform through hardlinks
  (PS2 to PS5SX2 and PS5 RetroArch).
- BIOS sync: for PS2-class emulators it copies exactly one BIOS, chosen from five preferred MD5s (USA v2.30
  first) or else the first verified 4 MB image (`src/firmware.c`, `PS2_PICK`, `make_plan`). An
  unverified BIOS is skipped; any RomM BIOS already in the folder blocks a better one. Other platforms'
  BIOS went flat into RetroArch's `system/`, where the Saturn core does not look.
- RommPS writes no RetroArch playlists.

## 6. EmulationStation in PS5 RetroArch

ES-DE runs with `--gamelist-only`. On every start the title builds `custom_systems/es_systems.xml` and
the gamelists from RetroArch's playlists in `/app0/playlists` plus a scan of `content/<system>/`
(`frontends/es-de/ps5/library_ps5.cpp`, `src/ps5_library.c`). Its log is `es-de/es-de-ps5.log`.

The content scan drops every file whose name starts with the stem of any core's firmware file:
`is_firmware()` compares against the firmware of all cores by prefix. ScummVM lists `tony.dat`, so
"Tony Hawk's Pro Skater 3 (USA).iso" never appears. Confirmed on the console with two dummy files,
`Tony Test.iso` (hidden) and `Test Tony.iso` (listed). Reported as
github.com/mihawk-99/PS5_RetroArch/issues/88.

A playlist entry is not subject to that check. A hand-written `playlists/Sony - PlayStation 2.lpl`
(version 1.5, `core_path` `/app0/cores/ps5sx2_libretro.so`, `path` under `/app0/content/ps2/`) brings the
game in. The PS2 core inside RetroArch is PS5SX2 (`ps5sx2_libretro.info`), not LRPS2.

## 7. Background services while RetroArch runs

While PS5 RetroArch was open, FTP, elfldr, the RommPS web UI, ShadowMountPlus and the forwarder
launcher all refused connections; after closing it they answered again without being re-sent. The
kernel side of the jailbreak stayed active. Consequence: an Output can only push while no RetroArch
session runs, and RommPS does not sync during play.

## Consequences for a PS5 Output

- Install through the catalog API plus FTP, then trigger and check a ShadowMountPlus scan.
- Launching is per target: PS5 RetroArch through forwarders or playlists; PS5SX2 through its own game
  tiles until it accepts `--rom`; ports by title ID.
- The Output should write RetroArch playlists, not only place files: that is what feeds EmulationStation,
  the WebUI and RetroArch alike, and it avoids the content-scan bug.
- BIOS: place per emulator path, prefer the BIOS RommPS would pick, and do not leave a second copy that
  blocks RommPS.
